# Project overview

## Purpose

This is a Persian, RTL Laravel application for an education consultancy. Staff create consultation slots and reservations; students use a secure public link to complete missing information, upload required payment receipts and view a published field-selection plan.

## Stack

- PHP 8.3, Laravel 13 and SQLite by default (MySQL is supported through environment settings).
- Blade views, Vite, Tailwind CSS 4, Bootstrap 5, Vazirmatn and a Persian date picker.
- `spatie/laravel-permission` for roles and permissions; database-backed queue and session drivers are the intended defaults.

## Main areas

| Area | Main code | Responsibility |
| --- | --- | --- |
| Authentication and access | `app/Http/Controllers/AuthController.php`, `app/Http/Requests` | Phone-based account registration/login and validated requests. |
| Admin reservation operations | `app/Http/Controllers/Admin/ReservationController.php`, `app/Services/ReservationService.php` | Create, edit, cancel, move, complete and mark no-shows. |
| Availability | `app/Services/SlotAvailabilityService.php`, `app/Models/ReservationSlot.php` | Prevents overlapping consultant appointments and follow-ups. |
| Public student flow | `app/Http/Controllers/PublicAccess/PublicReservationController.php` | Token-protected completion, receipt and report-card upload, and public plan viewing. |
| Payments | `app/Services/PaymentApprovalService.php` | Stores receipts privately and moves payment/reservation statuses after approval or rejection. |
| Field selection | `app/Services/FieldSelectionService.php`, `app/Models/FieldSelectionPlan.php` | Builds draft plans from the study-program catalogue, supports ordering, publication, versions and public visibility. |
| Study programs | `app/Services/StudyPrograms`, `app/Console/Commands/*StudyPrograms.php` | Streams and normalizes Iranian study-program XLSX files, imports them idempotently and keeps review rows separate. |

## Reservation lifecycle

`draft` → `pending_completion` → `pending_prepayment` (when required) → `pending_payment_approval` → `confirmed`.

The terminal outcomes are `payment_rejected`, `expired`, `cancelled`, `completed` and `no_show`. Transactions and row locks protect reservation changes; availability checks also consider other appointments of the same consultant on the same day.

## Data model

The central `Reservation` links a `Student`, `ReservationSlot`, `Advisor`, optional `ReservationPayment`, documents and follow-ups. Supporting operational records include users/roles, settings, payment cards and activity logs.

The study-program catalogue is normalized around exam years and groups, provinces/cities, institutions/campuses, academic fields, course types and admission types. `StudyProgram.identity_hash` is the import identity, while `source_hash` detects source changes. The 1404 snapshot lives in `database/seeders/data/study_programs_1404/`.

## Entry points

- Web routes: `routes/web.php`.
- Scheduled expiration: `reservations:expire`, registered in `routes/console.php` and intended to run every five minutes.
- Study-program operations:
  - `education:import-study-programs`
  - `education:audit-study-programs`
  - `education:backup-study-programs`
  - `education:reset-study-programs`

## Access control and storage

The seeded roles are Super Admin, Admin / Branch Manager, Operator, Accountant and Consultant. Route permissions enforce operational access, while Super Admin is globally allowed by `AppServiceProvider`.

Receipts and report cards are stored on the local/private disk and served only through protected routes. Public reservation access is controlled by per-reservation tokens and can be disabled or regenerated by staff.

## Development and verification

```bash
composer install
cp .env.example .env
php artisan key:generate
php artisan migrate --seed
php artisan db:seed --class=StudyProgramsSnapshotSeeder
npm install
npm run build
php artisan test
```

The test suite covers registration validation, Persian date conversion, study-program normalization/import idempotency, field-selection publication and visibility, reservation prepayment rules, consultant slots and conflict handling.
